# Trust and security model

ModelBlame consumes model checkpoints, datasets, ledgers, and declarative specifications. Those artifacts can be malformed or adversarial. It also executes local training adapters, which are Python programs with the privileges of the invoking user. These are different trust domains and must not be blurred.

## Security objectives

For v0.1, the implementation aims to provide:

- **integrity**: reject artifacts whose validated content does not match its bound hash or schema;
- **non-execution of data**: parsing a manifest, patch, ledger, certificate, or tensor file must not execute code embedded in that file;
- **path confinement**: untrusted relative paths must not escape the declared input or output root;
- **source-run immutability**: audit and counterfactual replay must not modify the recorded source run;
- **experiment separation**: reducer code cannot access a sealed holdout through the ordinary search evaluator;
- **bounded work**: inputs and configurations are subject to practical size, depth, count, timeout, candidate, and replay-budget limits;
- **evidence binding**: certificates bind the run, code/environment identities, contract, patch, checkpoints, results, and generated files by canonical hashes.

These properties do not make ModelBlame a sandbox for hostile Python or a cryptographically authenticated provenance service.

## Trust boundary

### Trusted local code

The following can execute code and therefore must be installed, selected, and reviewed as trusted:

- ModelBlame itself and its Python dependencies;
- the selected experiment adapter and any modules it imports;
- PyTorch, CUDA, tokenizer, and model implementation code;
- local CLI launchers and the operating system;
- optional Hugging Face or PEFT integrations explicitly enabled by the operator.

An adapter is not a declarative plugin. Its `build_experiment`, batch construction, loss, checkpoint, gradient, and evaluation methods run with the user's process permissions. A fresh replay subprocess isolates Python state and failures; it is **not** an operating-system security sandbox. Run untrusted adapters only inside a separately provisioned container or VM with appropriate filesystem, credential, and network restrictions.

The recorded Hugging Face adapter pulls the installed Transformers package into
trusted executable code. A local model directory stays untrusted data. The v1
adapter allowlists concrete `GPT2Config`/`GPT2LMHeadModel` and reads only a
bounded local `config.json`, plus one unsharded local `model.safetensors` for
pretrained initialization. It rejects custom and auto mappings, quantization,
sharded weights, and `.bin`, `.pt`, `.pth`, `.pkl`, `.pickle` or `.ckpt`
artifacts. It never enables remote code, contacts a Hub, or downloads a model or
tokenizer. The separate guarded loading helper forces `local_files_only=True`,
`trust_remote_code=False` and `use_safetensors=True`.

These restrictions stop model data from selecting new Python code. They do not
make the installed Transformers implementation untrusted-safe. Review and pin
that dependency as executable code. The recorded adapter accepts Transformers
4.57.x and requires the exact recorded version during checkpoint construction.
Audit and branch replay require its full recorded adapter compatibility object
to match.

### Untrusted data

Treat all of the following as untrusted even when generated by a previous ModelBlame run:

- experiment TOML and behavior/control YAML or JSON;
- JSONL and Parquet datasets;
- run, dataset, checkpoint, index, and bundle manifests;
- history ledgers and metrics;
- patch and certificate files;
- checkpoint JSON metadata and SafeTensors payloads;
- filenames, output paths, adapter identifiers, and hashes embedded in any artifact.

A trusted producer does not remove the need to validate later reads: files may be truncated, corrupted, moved, partially copied, or replaced.

## Deserialization policy

Run artifacts do not use Python pickle, `torch.load` on pickle-backed files, `eval`, `exec`, dynamic imports named by a manifest, YAML object constructors, or other general object-deserialization mechanisms.

Tensor state is stored in [SafeTensors](https://github.com/huggingface/safetensors). Primitive metadata is stored in bounded JSON, TOML, YAML-safe mode, or typed Parquet. Parsers must validate before allocating or using values:

- schema version and allowed keys;
- string lengths and collection sizes;
- nesting depth and total file size where practical;
- integer ranges, including steps, spans, tensor dimensions, and budgets;
- finite floating-point values and operation-specific weight ranges;
- tensor names, dtypes, shapes, byte sizes, and offsets against the manifest;
- uniqueness and referential integrity of example, occurrence, batch, and checkpoint IDs.

SafeTensors prevents Python-object execution by design, but it does not authenticate a file or make arbitrarily large tensors safe to allocate. Hash and shape validation remain mandatory.

## Canonicalization and hashes

Content addresses use a versioned canonical JSON representation. A digest has meaning only together with its domain and schema version. For example IDs, patch hashes, checkpoint hashes, and bundle hashes must not reuse an ambiguous untagged serialization.

Verification follows dependencies from the outer bundle inward and recomputes bytes or canonical objects rather than trusting a stored `hashes.json`. Hashes bind content; they are not digital signatures. An attacker able to replace both an artifact and every expected digest can create a self-consistent forged bundle. Authentic distribution requires an external signed release, transparency log, or trusted transport, none of which v0.1 provides.

## Path confinement

Every path derived from untrusted input is interpreted relative to an explicitly declared root. Before opening or creating a file, the implementation must:

1. reject absolute, drive-qualified, UNC, device, empty, and parent-traversal paths;
2. normalize the candidate and resolve existing path components;
3. require the resolved target to remain beneath the resolved root;
4. reject unexpected symbolic links, junctions, or reparse points when they could cross the boundary;
5. use exclusive or atomic creation for outputs and avoid following a replaced target at finalization.

Filename allowlists are preferable for fixed layouts such as checkpoints. The verifier never writes into the evidence bundle it is checking. Replay writes only to a new isolated output directory and opens the source run read-only by convention and validation.

Path validation reduces traversal risk but cannot eliminate all time-of-check/time-of-use races against a concurrent privileged filesystem attacker. For hostile multi-user systems, use OS-level directory ownership and container mounts.

## Patch language

A patch is data, not a script. Version 1 accepts only its enumerated operations.
Occurrence-targeting validation requires:

- an exact source run ID and run hash match;
- the behavior-contract hash expected by the experiment;
- a nonempty, bounded, duplicate-free list of known occurrence IDs;
- one declared normalization mode;
- no path, command, module, callable, or expression fields;
- no conflicting operations over the same occurrence.

`RESERVED_SLOT_INJECT` additionally requires the built-in adapter, a positive
declared slot count, exact membership in a recorded trailing no-op row, and the
recorded fixed-denominator injection weights.

Unknown operation names, unknown keys where the schema is closed, excessive nesting, non-finite numbers, invalid reweight values, duplicate conflicts, and unresolved selectors are rejected before a replay process starts. Human-friendly selectors are resolved once to occurrence IDs; replay does not re-evaluate mutable queries such as “all rows from source X.”

## Checkpoint safety and atomicity

A checkpoint is valid only after every required file has been written to a sibling temporary directory, parsed back, shape-checked, hashed, and atomically renamed to its final step directory. A directory with missing files, a temporary name, or no completed manifest is not a checkpoint.

Optimizer tensors are keyed through stable parameter names and validated against current model parameters. Python object IDs are never serialized as identities. Scheduler, scaler, RNG, sampler, packing, cursor and model-alias metadata use explicit versioned primitives. Alias groups bind tied state-dict entries to the storage topology of the reconstructed trusted model. Loading rejects extra or missing mandatory state, changed alias topology and unequal tied values. It does not silently initialize defaults.

The loader verifies the tokenizer and dataset fingerprints before reconstructing a batch. A changed source row, packing policy, tokenizer vocabulary, parameter mapping, or optimizer tensor is a replay incompatibility, not a warning to ignore.

## Process execution

Counterfactual branches run in fresh child processes with:

- an argument-vector API rather than a shell command string;
- an explicit minimal environment;
- a fixed working/output directory;
- a hard timeout and process-tree termination policy;
- captured stdout, stderr, exit status, and diagnostics;
- no modification of the source run;
- a unique temporary destination atomically promoted only on success.

The subprocess boundary protects experiment isolation and timeout enforcement. It does not constrain a malicious trusted adapter. Network access is not needed for the built-in harness and is never initiated automatically.

## Resource exhaustion

Valid-looking artifacts can still attempt denial of service. The implementation bounds work before expensive allocation where practical:

- maximum manifest and contract byte size and nesting;
- maximum string, probe, operation, and occurrence counts;
- tensor rank, dimension, element-count, and aggregate checkpoint limits;
- Parquet row-group and selected-column reads rather than unconditional full-history loading;
- candidate limit, projection dimension, worker count, beam width, replay budget, and wall-clock timeout;
- bounded on-disk replay caches with content-addressed entries.

Research configurations may deliberately raise these limits. The selected values belong in the run or evidence metadata so results remain interpretable.

## Holdout integrity

“Sealed” means inaccessible through the reducer API, not encrypted. Search receives a contract view without holdout observations. Final verification consumes a one-shot holdout capability bound to the contract hash and completed candidate hash, and records the unseal event. A second read under the same contract version fails.

This protects against accidental adaptive tuning in the normal program flow. It does not protect against an operator or adapter that reads the holdout file directly. Organizational separation or encryption can be layered on when adversarial analyst behavior is in scope.

## Evidence verification and mutation resistance

Verification reconstructs the dependency graph rather than trusting summary fields. At minimum it checks:

- source run and dataset/tokenizer identities;
- checkpoint and counterfactual tensor hashes;
- adapter and training-code identity;
- behavior and control contract hashes;
- canonical patch hash and occurrence membership;
- replay experiment hashes and environment compatibility;
- original, search, holdout, and control results;
- every recorded one-minimality experiment;
- generated artifact hashes.

Changing an occurrence ID, checkpoint hash, threshold, normalization mode, candidate group, fingerprint, tensor, control result, or generated file must invalidate the affected dependency and therefore the bundle. A valid hash graph establishes integrity relative to its inputs; it does not establish that trusted adapter code implemented the declared semantics honestly.

## Data privacy

Run artifacts necessarily expose dataset structure, stable hashes, timing, sources, and influence/effect metadata. Those values may themselves be sensitive or enable linkage attacks. By default, evidence artifacts include IDs and hashes, not raw examples. Raw text is included only with `--include-example-text`, and reports state whether redaction was used.

Hashing low-entropy text is pseudonymization, not anonymization: an attacker can hash guesses. Store runs and bundles under the same access controls as the underlying training data. ModelBlame does not upload data, checkpoints, telemetry, or reports automatically.

## Explicit non-goals

The v0.1 trust model does not claim:

- safe execution of arbitrary or hostile adapter code;
- authenticity without an external signature or trusted channel;
- confidentiality from local users who can read the run directory;
- robustness against a compromised OS, Python runtime, PyTorch build, or GPU driver;
- protection from all filesystem races on a hostile shared host;
- privacy, differential privacy, membership protection, or legal compliance;
- that a SafeTensors file is semantically benign merely because it cannot contain pickle code;
- that replay evidence proves the source data's real-world truth or lawful provenance.

Report suspected parser, path, or verification flaws privately to the maintainers before publishing exploit details.
